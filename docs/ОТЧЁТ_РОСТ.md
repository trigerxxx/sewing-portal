# Короткий отчёт: проект вырос или ухудшился?

Дата: 06.11.2026

## Цифры

| Показатель | Значение |
|---|---|
| Код приложения | ~13 600 строк (было ~5 000) |
| API-методов | 78 |
| Таблиц в SQL | 18 |
| Тестов | 40 (все проходят) |
| Листов в Excel | 55 (было 46) |
| Мобильные приложения | 2 APK + 2 PWA (iOS) |
| Документов | 7 |
| Заказов FBS в базе | 85: новых 13, в поставке 71, отменён 1 |

## Что стало лучше

1. **Склад реально работает офлайн** — снимок данных, очередь операций, синхронизация.
2. **Заказы WB подтягиваются сами** — новые, в поставке, отменённые; статусы сверяются с кабинетом.
3. **Сборка через сканер** — общий экран, списание со склада в момент сборки.
4. **Кабинеты настраиваются в интерфейсе** — токены заводятся складом, не в коде.
5. **SQL-слой и сверка** — можно сравнить файл и сайт: «в файле / списано WB / на сайте».
6. **Тесты** — 40 проверок вместо нуля: импорт, идемпотентность, сборка, отмены, экспорт.
7. **Меньше лишнего в интерфейсе** — осталось «Склад / Магазин / Заказы WB».

## Что стало хуже или рискованнее

1. **Сложность выросла втрое** — 4 новых модуля (wb_api, wb_sync, fbs_stock, cex), больше точек отказа.
2. **Данные теперь в двух местах** — Excel и SQL. Без сверки легко получить расхождение.
3. **Были инциденты** — дубли заказов (72 вместо 58), скрытая корзина, неработающая кнопка «Сохранить кабинет», клиент видел склад. Все исправлены, но показывают цену роста.
4. **Зависимость от API WB** — лимиты (1 запрос в минуту на статистику), формат ответов, токены.
5. **Excel остаётся хрупким** — 5 отрицательных остатков в файле, книга в Google Drive.
6. **Нет git-истории** — откат только через бэкапы (база раз в день, книга перед записью).

## Вывод

**Проект вырос, а не ухудшился** — по возможностям. Но выросла и сложность: теперь важны дисциплина обновления, резервные копии и сверка.

Оценка: функциональность +, надёжность ±, простота −.

## Что сделать, чтобы рост не превратился в проблемы

1. Раз в неделю — «Сверить остатки» и смотреть расхождения.
2. Не нажимать «Обновить из WB» подряд (лимиты).
3. Хранить книгу локально (или копию), не только в облаке.
4. Перед крупными изменениями — бэкап базы и книги.
